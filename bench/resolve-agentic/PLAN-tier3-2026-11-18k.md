# PLAN — Tier 3: friction/efficiency intervention wave (2026-11-18k)

Goal: measure the effect of the Tier 2-adopted naming rule (variant B) on agent FRCTION —
mangled-name attempts, tool uses, harness time — with the pass axis recorded but never the
headline. The pass axis is saturated (SATURATION.md §1: one flipped trial = 5.6 points;
90% power against a 5-point regression needs n=45); the friction columns have real spread
and are where a rule like B can actually move something.

## Design — two arms, one project, identical stack

- Stack for BOTH arms: **MCP 5.3.3 / opencode 2.3.1 / Splash 1.7.0 daily config (effort
  medium)**. Traps re-armed on 5.3.3 the same day (rearm-traps-_mcp_17j_rearm.json): F1 loss
  set {speed, retime, audio_in_step, link} 3/3, F2 {grade, link} 3/3, T2 marker dict-shape,
  T8 comp_count — the suite is valid on this stack before any trial runs.
- **Arm A (control)**: trial `AGENTS.md` exactly as every published wave ships it
  (`trial_agents()`, no naming guidance) — reps **r1–r3**.
- **Arm B (rule)**: `trial_agents()` + the EXACT Tier 2 probe-B sentence (same bytes as
  `probe_mangle_driver.py RULE`), reps **r4–r6**.
- Pairing per brief: (r1,r4), (r2,r5), (r3,r6) run back-to-back, and briefs run in the fixed
  published order (T1 T2 T3 F1 T7 T8 F2). Warm/cold engine cannot favour one arm: every pair
  shares a moment, and each brief's 6 sessions straddle any drift.
- 7 briefs × 6 reps = **42 sequential sessions**, single project `_mcp_AGBench-2026-11-18k`
  (the 17h single-project design, kept verbatim). Fixture copies extended to `_f1s1..6`,
  `_f2r1..6` (duplicated from the ARM-CHECKED templates like the builder's duplicate stage).
- Seal: unchanged 17h protocol — global `AGENTS.md` hidden (now with the 2.3.1 CLAUDE.md
  fail-closed gate), MCP-trio census with 17g semantics, harness drift log, engine config
  proof, per-trial snapshots; in-trial snapshot grades T8 as before.
- Tenancy: operator session shares the engine throughout — disclosed, as always.

## Headline measures (per arm, per brief, medians)

1. **Mangled-name attempts** (`mangle_analysis.py`, unchanged) — the Tier 2 quantity.
2. **tool_use_count** and **wall_s** (already in `wave_summary.jsonl`).
3. **Wasted harness ms** on mangled attempts.

Baseline cross-reads (confounded, disclosed, never used as the rule effect):
- Arm A vs 17h pass 2 → stack-move effect (5.3.1→5.3.3 + 2.3.0→2.3.1) mixed with tenancy.
- Arm B vs 17h pass 2 → same confound plus the rule.
**The only clean read is Arm B vs Arm A on this stack.** n=3 per brief per arm: sized for
medians of a continuous quantity, not for pass-rate inference (SATURATION's detection-power
tables apply to the recorded pass axis only).

## Pass axis (recorded, secondary)

Graded exactly as 17h (read-backs only, claims extraction, `grader_selftest.py` green first)
with `grade_baseline_17h.py --reps r1,r2,r3,r4,r5,r6`. Expect 6/6 per arm per brief; a flip
in arm B only would be a naming-guidance hazard signal and gets its own investigation before
the rule stays adopted.

## Ship/don't-ship rule for the change

Keep the B rule in trial contexts if (a) arm B median attempts/arm ≤ arm A, and (b) no arm-B-only
grading flips. Otherwise revert and note the probe's p≈0.12 as insufficient. Either outcome is
recorded; the Tier 2 probe decision was explicitly "adopt pending wave confirmation".

## Order of operations

1. Build fixture `_mcp_AGBench-2026-11-18k` (all stages, ARM CHECK OK) + duplicate f1s4..6 /
   f2r4..6; capture prestate + ground truth (sealed, sha recorded).
2. `grader_selftest.py` green; grader gets `--reps` (default = historical behaviour).
3. Smoke one session (`T1r1`) end-to-end on the new stack.
4. Dispatch the wave (background), snapshot + seal audit per trial.
5. Grade, scan friction per arm, publish `results-tier3-2026-11-18k.json` + wave README,
   teardown the project, commit/push.
