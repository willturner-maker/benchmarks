An agent benchmark you can actually reproduce

τ²-bench grades an agent from the end state of a scripted environment — a database hash, in-process assertion replay, a substring check — not from a judge's opinion. That is what makes it worth running, and what makes it hard to fake. Splash + Qwen3.8-Flash-Next IQ3_S scored pass^1 0.870 (airline) / 0.791 (retail, judge-free subset) / 0.873 (telecom) over 476 simulations, all scored, zero infrastructure errors. The number that decides how to read the others: 45 of 238 tasks flipped between two temperature 0 trials.

2 · pass^1 − pass^2 is the flip count the stability finding

Per domain: pass^1 vs pass^2, and what the gap costs
τ²'s pass^k is per task C(n_pass,k)/C(n_trials,k) averaged over tasks — with 2 trials, "both trials passed". So the gap is not extra information: it is the count of tasks whose two greedy trials disagreed. Hover a bar
pass^1pass^2the looser independent-trials variant (mean p^k), for contrast

Where the flips appear (triaged after publishing, over the local transcripts): 37 of the 45 first diverge at a user-simulator turn — 33 of those at the opening sentence — and only 8 of 238 tasks (3.4 %) diverge in the agent's own turn under an identical prefix. Under self-play both roles are the engine under test, so this locates the flip rather than excusing it. A trap closed: τ² sends a per-trial seed (626729 / 373753), but this engine gave byte-identical greedy output for both seeds (3/3 unloaded probes), so reseeding is not the mechanism and no seeded replay exists here. Direction is near-symmetric (24 down, 21 up): sampling, not drift. Two trials is still the floor of what this repo publishes, and a third would move pass^2 materially — stated rather than smoothed. The batching story was tested and refuted: the same 8 flipping tasks re-run detached at --max-concurrency 1 produced 19,439 width-1 decode batches and none wider, and still flipped 3 of 8 — the same count as the width-3 replication. Full control: the width-control report.

Those 40 call gpt-4.1-2025-04-14, and on v1.0.1 there is no way to point that at a local model: it is a constant in config.py (no getenv in the file), there is no CLI judge flag, and the engine takes a single --model with no alias. The smoke run proved the cost of ignoring this before the wave: litellm.NotFoundError, 3 retries each, then infrastructure_error, reward: null and 0 messages — the finished dialogue is thrown away. 3 of 5 smoke retail tasks died that way.

Excluded with upstream's own --task-ids (ids in the runner), so no benchmark data was edited. And a trap for anyone looking for a shortcut: retail's train/test split is also 74/40, but it is a different 74/40 — set-compared — so --task-split-name train is not a judge-free switch.

τ² re-sends a session's whole context every turn across 20–60 turns — the exact shape persistent KV caching exists for, and the reason 3.6 % of the prompt volume cost anything to prefill. Window rates: decode ≈310 tok/s, itl_ms p50 7.94 → 9.68, ttft_ms p50 172.5 ms, draft acceptance 63.9 % (2,358,289 drafted / 1,506,035 accepted). The window prefill figure (≈1,468 tok/s) is not a throughput claim: it is cache-hit-dominated with tiny prefills and block-probe overhead, and is not comparable to wave 19b's flat 3,485–3,499 tok/s.

5 · Tenancy of this window the smoke run was the opposite case

878 /status samples at 10 s over 146 min, attributed by prompt_tokens size: 2,575 benchmark request-samples (all resident, ≤15,629 tokens) against 3 co-tenant samples — this operator's own chat session at up to 87,043 tokens in spill mode, ~30 s of the window. The wave ran detached and operator-idle.

Two days earlier the smoke run showed what happens if you don't: the operator session (221,058 tokens) accounted for 94 % of peak residency and every spill/demote delta, while τ²'s own traffic was 0.09× the budget. Every engine-side claim on this page comes from the wave, not the smoke.

6 · Reproduce it no container, no VM, no GPU toolchain, no footage

git clone https://github.com/sierra-research/tau2-bench ~/tau2-bench
cd ~/tau2-bench && git checkout v1.0.1 && uv sync          # not on PyPI
~/benchmarks/bench/tau2-bench/run_wave.sh ~/my-wave
python3 ~/benchmarks/bench/tau2-bench/summarize.py --wave-dir ~/my-wave \
  --domains "airline retail telecom"

Any OpenAI-compatible endpoint works (TAU2_LLM_ARGS); LiteLLM splits the model string at the first /, so registry ids with / and : survive intact. A community row must state: host, engine, model + quant, tag and commit, trial count, whether the user simulator is self-play or cross-model, the task scope (which retail subset), and which pass^k definition it is quoting. Re-derivation is a first-class feature: summarize.py reproduces τ²'s own printed Average Reward/Pass^1/Pass^2 and its DB-match and annotated-action counts for all three domains, and --from-rows recomputes every headline above from the published per-simulation rows alone.
