The KV ceiling was never KV — it was a request count of 32

A KV-pressure run died at width 40 with HTTP 503. A ten-minute probe with tiny prompts pinned why: request 33 is refused instantly, memory gauges untouched, body frontend_overloaded — the documented --queue-size default. So the morning shipped a stack move (--queue-size 64) and a rebuilt driver, and the afternoon wave ran the KV stage past the wall: 48 concurrent 55k-token requests, all admitted, none refused, and 17.04× the resident KV budget with nothing tripping.

  • The flag was the whole wall. 48 concurrent ~55k-token requests, all admitted, zero refusals — where the same instrument refused at 33. Widths were deliberately capped at 48 to leave 16 lanes of slack under 64, so a refusal would have meant the engine's limit rather than our own saturation.
  • The surprise: queueing is invisible at the admission gate. The prediction was that past 32, admission.waiting and waiting_memory would finally measure something. They peaked at 0 in every single round — as did waiting_concurrency and held_behind_refusal. Requests are admitted into lanes and the wait relocates to the scheduler's prefill queue, which the ladder's own peak_queued (8 / 8 / 16 at w12 / w24 / w32) proves exists. A monitor reading admission.* would call this engine idle at width 48.
  • Width past 32 is paid for in wall time, at flat prefill: 189.5 s → 760.1 s, with prefill pinned at 3,485.4–3,499.1 tok/s (±0.2 %) — the same line the morning run measured below the wall (3,513.7–3,520.7). Mechanism: maximum_batch_width = 4, corroborated by the session's decode batches (b1 4,375 / b2 278 / b3 244 / b4 3,434).
  • KV residency untouched at 17×: pages_active pinned at 1,920 pages = 61,440 tokens (39.5 % of budget) on all six rounds — it stepped up once from 1,654 pages when in-flight passed 32, then stopped moving, while summed contexts went to 2.65 M tokens. Governor headroom never below 207.8 MB.

3 · How the wall was found — three flaws in the morning instrument, all fixed 11-19 ext → 11-19b

  • A refusal killed the run and its summary. The sealed chat() raises on non-2xx, so w40's 503 ended the driver mid-stage and the SUMMARY was lost. 19b wraps every request and records the refusal (code + body) as the round's outcome.
  • Cross-run prompt reuse made two "controls" measure nothing. The generator is deterministic, so the w2 / w12 stitch controls were byte-identical to the 11-18 prompts and --persistent-cache served them from disk: 93,530 tok in 0.4 s and 612,180 tok in 1.5 s, with prefill_rows moving only 26 and 84. Those rows prove the cache works. 19b seeds a fresh namespace and marks any round cache_served unless prefill_rows tracks prompt tokens — here it equalled prompt tokens on every round, so all six are real pressure.
  • The stop rule watched a gauge this build does not move. "Wait for a suspension event" is useless when the answer to KV pressure is spill and disk demotion: the morning run sat at 1,654 active pages while lifetime spill moves reached 28,138 and disk demotions 4,390 (41 refused). 19b's rule is refusal / admission.suspended / suspension-counter delta / kv_demotions_refused delta / capacity_failures delta.
  • Gate validity. A gate must use the same primitive as the baseline it certifies — the morning's prose-prompt gate read "cold" while the ladder was fine.

4 · Caveats and what this instrument can no longer answer

  • Not a clean window. The operator's session is served by this same engine and took turns during the run, including inside the KV rounds. Per the standing 11-13 finding the tax lands on latency cells, so "best w1 on record" carries it and a detached single-tenant re-run of the ladder is owed.
  • The restart broke the lifetime-counter column. Flags bind at launch, so the engine restarted and every lifetime counter began at 0 — the cleanest per-round deltas in the series, but 11-18 began at 43 and 19-ext at 45, so lifetime reads stop being comparable across rows. Related: at run end lifetime disk.kv_demotions read 421 with 5 refused, while every KV round's delta was 0 — those came from the gate/ladder legs, attributed by delta rather than by the lifetime read.
  • Both stack moves landed in one launch (queue-size 64 + thinking budget 16,384 → 32,768). The second is inert for this suite — ladder outputs are pinned at 512 tokens and KV outputs at 8 — but the ladder is the comparable-throughput check that proves it, and it came back better, not perturbed.
  • Summed-volume KV is bounded out. At 17× the governor still reports no work, and the only failure mode beyond that is a request-count flag. The live question is depth, not volume: context_bounds puts resident at 155,633 against a 262,144 window, and the open probe is one context walking toward the resident line while held across turns — what real agent sessions do, and what no wave here has measured directly.
