Agentic benchmark — method

Fresh agents, independent grading, three full passes

Six tasks per run (read-only inspection, marker placement, ripple insert at a cut, locked-track delete recovery, a full render loop, and a Fusion-comp API trap). Each task went to a fresh subagent with no prior conversation — uncontaminated tool-use ability — executed in three two-agent waves sharing one Resolve. The suite ran three times (n=3).

Grading never trusted the agent. Every outcome was verified afterwards by independent grader read-backs: timeline probes, ffprobe on the rendered file, and scans of the server's operation/execution logs. Efficiency is harness-measured tool-uses and wall time, not self-report.

Honesty — caught by graders, not by self-report

  • R1 · T8Rejected its own create_fusion_clip “success”: read-back showed 0 comps, so it rebuilt a plain clip and used timeline_item_fusion.add_comp — the route that creates a real, enumerable comp.
  • R1 · T7Handed back a placeholder mid-task, then owned it when pushed and delivered the real verified report.
  • R2 · T3Investigated a source-start reading 1 frame low (29.97 DF) with two code paths, declined to +1-compensate, kept the instructed placement — correct call.
  • R3 · T2Found a foreign item contaminating its own timeline (a concurrent worker crossing over), removed it, and reported the interference instead of grading itself down silently.
  • R3 · T7Caught its render job bound to another worker's timeline (agbench3_T8 in list_jobs TimelineName), cancelled, re-queued against its own, and verified the output before claiming done.

Concurrency — the dominant hazard

  • bindingprepare_render_job binds whichever timeline is current at call time — with two workers on one Resolve, one agent's job rendered the other's timeline into its own output directory. Always check the job's TimelineName snapshot before starting.
  • flappingThe current timeline switches under a worker mid-sequence (three separate runs hit it). Recovery that worked every time: re-set_current immediately before each mutation, and address everything by timeline_id/pinned rather than “current”.
  • archivingThe server auto-archives <name>_archived_vNN timelines before destructive ops — a side effect every agent had to be told about or discover; cleanup must delete those too.
  • verdictSingle-agent usage is clean; shared-engine multi-agent needs pinning discipline and job-timeline checks, and one agent's efficiency numbers then partly measure the other's traffic.

Concurrency sweep — 4 November, two tiers

How wide can we run before it stops paying off?

Tier 1 — engine only, no LLM: bursts of 1→16 simultaneous MCP calls, read from the server's own step records. Server-side processing time is flat at every width — get_current 0–2 ms and the timeline probe 6 ms (video-only) / 32–37 ms (full) at N=1 exactly as at N=16. The Resolve bridge never degrades; end-to-end the agent harness dispatches only ~3–4 MCP calls/s total across all agents. LLM turn time, not Resolve, is the concurrency ceiling.

Tier 2 — agentic: fresh agents, one battery (read · ripple-insert · render-loop · Fusion-trap) run at width 1 sequentially and width 4 with four agents on one Resolve simultaneously, two passes each, graded only by independent read-backs. Width-2 figures come from the n=3 scorecard above.

API quirks confirmed across the passes

Candidate api_truths for this build (MCP v4.18.5 · Resolve 21.1.2.10)

QuirkWorkaround / truth
create_timeline_from_clips refuses a bare callclip_infos entries require record_frame; the tool lives on media_pool.
append_to_timeline silently drops unplaced clipsclip_infos require track_index (add media_type:1 for video-only); without it, entries can vanish.
ripple_insert throws MISSING_RECORD_POINT after the confirm tokendry_run defaults to true; executing needs an explicit dry_run:false + token, sent in the dry-run's exact accepted shape.
Confirm-tokens are issued per actiondelete_timelines/delete_clips always ask once; render.delete_job often doesn't. Don't assume a token flow that isn't returned.
DF-timecode source readers show 1999 for a head at 2000Timecode-anchored reads on 29.97 DF; duration and placement are the truth — never +1-compensate.
prepare_render_job refuses /Volumes targetsPass require_temp_target:false; never render probes to /var/folders (outputs can truncate).
ResolutionWidth/Height in render settings are inertUse FormatWidth/FormatHeight as integers (cost run 3 a detour).
GetRenderJobList() entries carry no Status keyPoll GetRenderJobStatus(jobId); also, StartRendering can return success while a job sits Ready — verify the job, then re-prepare if wedged.
create_fusion_clip items expose 0 comps to the APIThe success is a phantom; timeline_item_fusion.add_comp on a plain live clip creates a real comp — verify via get_comp_count.
Destructive actions refuse onceFirst call returns a confirm_token; the re-call with token executes (300 s TTL).
