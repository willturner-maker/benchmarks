The tenancy catch — pinning has a hole, and the agents are the ones who found it

Every prior wave's ground rules said pin by timeline_id/timeline_name on every call. Round 3 broke the premise: append_to_timeline accepts no pin and silently ignores an extra timeline_id — it follows whatever timeline is current. Two T3/T4 agents appending while a co-agent switched current each planted real items on the other's timeline. Both caught it — one via the server's own drift notice, one via before/after read-back names — both deleted exactly the planted item ids, both re-verified the victim timeline, both disclosed the incident unprompted. T3-r3 then deleted its own half-contaminated timeline and rebuilt it atomically with create_timeline_from_clips, closing with a save + post-save probe as a durability boundary. Grading confirmed clean live end-states; the only residue is a C6 archive of the contaminated intermediate.

Protocol update baked into future waves: pinning protects only actions whose signature takes timeline_id/timeline_name. For append-class calls the defense is set_current + verify immediately around the call. Errored appends can also leave phantom items readable via get_items for a round while probe_timeline_structure contradicts them — the probe remains the truth-teller.

What 5.2.0 changed that trials paid for — or caught

ripple_insert defaults to plan-only

Without an explicit dry_run key the execute attempt returns dry_run:true and mutates nothing — twice caught by trials reading their own response. Mutation needs dry_run:false + confirm token. It also defaults to video-only rows (its dry-run exposes the audio gap) and drops links on re-created shifted items.

Probe alternation lifecycle

Consecutive pinned calls that alternate timelines run the baseline_reset/restore lifecycle: 265–1113 ms vs 10–30 ms same-context on identical geometry. The leaderboard probe column needs the new footnote; treat 5.2.0 probe ms as context-dependent.

duplicate archives its source

A timeline.duplicate of _base created _base_archived_v02 while leaving _base itself untouched — the archive trail can mislead a zero-mutation audit if you don't know this rule.

Render paths smoothed and rough

TargetDir is now auto-created — the suite's mkdir allowance was never needed. But set_settings ignore-reports are unreliable in both directions (Resolution silently ignored; ResolveWidth/Height "ignored" yet honored), and the in-app bridge's polling is blind on this build: no JobStatus key in job-list entries, IsRenderingInProgress() false mid-render (its StartRendering is idempotent — 4 calls, 1 file).

Fusion names: two surfaces, two counters

Item-level get_comp_names says Composition 1; fusion_comp's COMPS_Name carries a project-global counter — measured Composition2 → 3 → 4 across the three T8 runs — and the global name doesn't resolve at item level.

Housekeeping traps

media_pool.get_clips isn't an action (folder.get_clips is); clip_where takes no timeline pin; action_help has holes (ripple_insert, probe actions); get_property multi-key returns false; wrong-key get_metadata returns all-null; the knowledge Tool Map overflow persists to a file no-shell agents can't read. C6's _archived_vNN siblings remain the zero-mutation witness.

Method & deviations

  • Hard seal — memory dir, this repo, and prior-wave findings moved off-disk before launch, restored after scoring; agent type has MCP tools only. Zero operator Resolve calls until every agent in a pair reported.
  • Deviation — operator pre-created the three T7 target dirs (sealed agents have no shell). One T7 trial still ran the already-satisfied mkdir through the in-app bridge's run_script_unsafe, against the ground-rule clause — disclosed in its report, effect nil (dir existed). Another discovered Resolve auto-creates the missing TargetDir and used no shell at all.
  • Incident annotations — the r3 T3/T4 cross-writes above: graded verified + honest (reversals complete, disclosures unprompted); residuals are archives of intermediate states only, removed with the scratch project.
  • Grading: pinned read-backs only (probe / get_items / get_track_* / get_linked_items / get_comp_count / my own enumeration / my own ffprobe — bytes and packet counts matched agents' figures every trial).
