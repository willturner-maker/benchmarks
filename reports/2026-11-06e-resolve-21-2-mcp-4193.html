Behaviour findings this pass

Audio enum silently drops

A clip_infos row with media_type: 0 returns success and the server even reports items_added: 2 — and the audio item never lands. The working enum is 2; a string raises an int() error. Found by an agent, reproduced by the grader.

end_frame is end-exclusive

Two independent trials wrote a 120-frame render from a 121-frame brief and diagnosed it from the server's own drift warning. Dry-run gap accounting also never credits an audio row, so it under-signals.

Lock guard: real, narrower than briefed

Armed with index (track_index is a loud MISSING_INDEX) and confirmed by get_track_locked, deleting an item on the locked track is refused with TRACK_LOCKED naming the track. Deleting the video item whose linked audio sits on that locked track is not refused at all — the guard inspects only the target's own track.

Two selector contracts, one object

timeline_item_fusion honours timeline_id/timeline_item_id and reports pinned: true. fusion_comp ignores them — now openly, via ignored_params: ["ignored timeline_id"] — and binds to the current timeline, so node enumeration needs set_current plus a bare call, bracketed by get_current.

A probe I mis-rated

probe_timeline_structure does honour timeline_id. Two trials believed it didn't and burned extra set_current calls; I had earlier mis-read its payload as the faulty part. The action returns no error for a selector it appears not to support — it just works.

Read-only proof from archives

Every mutation auto-archives the timeline as <name>_archived_vNN. The absence of that sibling is positive evidence nothing ever mutated a timeline — how each T1's zero-mutation claim was settled. The operation log can't do it: it records mutating ops with no params and no timeline names.

Methodology honesty

The wave's worst defect was mine, not the agents'. A machine-generated "results" notice arrived before run-1 pair 3 had actually finished; I trusted it, made grading reads while a live agent was still working, and pinned reads switched the current timeline under that agent. I then read a transient empty timeline and a not-yet-written output file and declared the pair invalid to the operator. Both trials were clean and are scored as such. The rule now in the runbook: no operator Resolve call of any kind — including pinned reads — until every agent in the wave has reported, and no agent hand-back or machine notice counts as evidence on its own.

Disclosed deviations: (1) T7 briefs allow exactly one shell command — mkdir -p of the render target, because the render tools refuse a target_dir that doesn't exist — added before dispatch and identical in all three runs; file verification stays MCP-side. (2) Sealing is procedural, not harness-enforced: repo and memory directories moved off-disk for the scoring window, and every brief forbade shell/file/web — no trial used any beyond the permitted mkdir. (3) Tool counts and wall times come from the harness usage block, not the operation log. (4) Nothing published here carries a real media path: this build's probe_timeline_structure echoes each item's absolute file_path, so no probe payload was pasted into a doc, report or commit message — the media is described by class and volumes appear as /Volumes/YourMediaVolume.
