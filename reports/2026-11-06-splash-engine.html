Concurrency scaling — past the dip, onto the plateau

The benchmark was upgraded twice mid-session. Final rule: escalate 1→2→3→4→6→8→12→16→24→32 and stop only when aggregate falls within 10% of the single-stream baseline. It never fired — there is no collapse by width 32. Same prompt, 512 output tokens, two rounds per width, /status sampled during every round.

KV pressure — chasing the first suspension

Width alone can never suspend anything (the transport caps at 32 requests). So v4 pushes the budget that matters instead: unique long-context prefills, ~46.7k tokens each, 8 output tokens — total live token demand climbing to 611,244, four times the resident KV ring of 139,264 tokens. A suspension would show on the gauge or the lifetime counters, which catch even instant-longer-than-a-sample parkings. Neither moved.

Agentic suite — headless Claude Code served by Qwen

Fresh session per trial, all model aliases pinned to the resident Qwen, minimum tool allowlists (curl-only for S1/S2/S3, Read-only for S4), no MCP inheritance, sequential trials. Graded by independent read-backs: constants exact-checked, arithmetic recomputed from the model's own echoed numbers, written files structurally validated, diagnosis on a rubric.

Method honesty

The first suite pass was discarded — orchestrator error, not model behavior. An allowlist override blocked the intended curl route; headless sessions inherited the operator's MCP servers (two agents fetched /status through the Resolve MCP's Python sandbox); one shared work dir let blocked trials discover the diagnosis fixture. Run 2 fixed all three (per-task allowlists, --strict-mcp-config, isolated task dirs).

The discarded run still yielded a signal worth keeping: 4 of 12 blocked sessions refused to invent numbers, one volunteered that its values came from the fixture rather than a live fetch. The refusal-to-fabricate check is now part of the suite.
