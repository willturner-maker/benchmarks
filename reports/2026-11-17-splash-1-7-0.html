2 · Batch A — the restart that silently no-oped clean-verifyrows · validity first

Intended A/B: --verify-rows all restart vs default. Batch A's ladder is valid, but the restart never happened: pkill -f "splash serve" matches the child while a supervisor (-m server[.]server) respawns it with stale args. The VALIDITY.md flags the whole A/B, the harness lesson is generalized (kill the supervisor too — bracket trick so the pattern never matches itself), and batch B re-ran it correctly with a banner that proves the mode. Also learned the same day: OpenCode v2.3.0 resolves shell/read paths against the launcher cwd, not the session cwd — which destroyed batch A's S3 artifacts.

4 · Standing findings from the 1.7.0 day

  • Engine state is part of the measurement condition. Minor bumps cold-start the prefix cache; every wave now records the warmth gate result, and cache wipes (any cause) demand a warm-up pass before numbers are comparable.
  • Engine restart recipe: kill supervisor and child; Splash has no stop subcommand; live engine is never restarted mid-suite.
  • Effort default: the agentic effort A/B (companion scorecard) set --default-reasoning-effort medium: xhigh paid ~3× median thinking tokens for no measured gain on the real suite.
